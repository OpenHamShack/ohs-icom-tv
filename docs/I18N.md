# Strings, the check and frequency formatting

The family's rules are `~/openhamshack/docs/contract/I18N.md`; this is how
they apply here. The beta ships English only, but no user-visible text may
live in code: everything a person reads comes from a catalog, so a second
language is a new file rather than a code change.

## Adding a string

Each module has its own English catalog:

| Module | Catalog | R class |
|---|---|---|
| `android/testapp` (the host: picker, sign-in) | `testapp/src/main/res/values/strings.xml` | `com.openhamshack.stationflow.testapp.R` |
| `android/kind-stationflow` (the Icom kind) | `kind-stationflow/src/main/res/values/strings.xml` | `com.openhamshack.kind.stationflow.R` |
| `android/core-candidates` | none yet; its two literals (`OK`, `Cancel` in `TvTextDialog`) are in the baseline | |

The kind keeps its own catalog because it moves into OpenHamShack Remote
whole. Put a string in the module whose code shows it.

- Compose: `stringResource(R.string.x, args…)`; plurals
  `pluralStringResource(R.plurals.x, n, n)` with `<plurals>` (`one` and
  `other` at least). Outside Compose: `context.getString(…)`.
- **Whole sentences, numbered placeholders**: `Connecting to %1$s…`, never
  `"Connecting to " + name`. A language may need the words in another
  order, and `%1$s`/`%2$s` lets it.
- **Never `n == 1 ? … : …`**: that is what `<plurals>` is for.
- Lists of parts: join with a catalog string (`list_separator` in the
  test app), not a literal `" · "`.
- Room to grow: a label 40% longer than the English must still fit. Prefer
  `maxLines = 2` to `maxLines = 1` for sentences.
- Add an XML comment above any string whose placeholders are not obvious.
- Not translated, ever, so no catalog entry: callsigns, locators, mode
  names used as identifiers (`FT8`, `USB-D`), protocol strings. Pass them
  in through a placeholder.

## Frequencies and numbers: ShackFormat

`com.openhamshack.i18n.ShackFormat` (in the kind) formats frequencies,
offsets, plain numbers and SWR the same way on every OpenHamShack platform
(contract §4): `ShackFormat.frequency(hz, locale)` gives `144.174 MHz` in
English and `144,174 MHz` in German, kHz with one decimal below 30 MHz, MHz
with three from there up, never grouped, with a no-break space before the
unit. `ShackFormat.offset(1500, "Hz", locale)` gives `+1500 Hz`. Take the
locale in Compose from `shackLocale()` (`ui/Locale.kt`), which reads the
same configuration as `stringResource`.

**Exception: the radio-shaped displays.** The main dial on the TV screen
and the radio faces (`docs/RADIO-DISPLAYS.md`, `radio/Faces.kt`) copy the
Icom's own LCD, and its `145.174.000` dots are what the radio shows, so they
keep `formatHz`. Everything that is our own layout (the Heard list today;
the Tune panel, toasts and SSTV captions when M3 reaches them) uses
ShackFormat.

### The copy, and refreshing it

`kind-stationflow/src/main/java/com/openhamshack/i18n/ShackFormat.kt` is a
verbatim copy of ohs-libs'
`kotlin/shack-i18n/src/main/kotlin/com/openhamshack/i18n/ShackFormat.kt`,
with a header naming the ohs-libs commit. It is copied because ohs-libs
publishes no Android artifact and this repo builds on its own. OpenHamShack
Remote carries the same copy; when this kind moves into Remote the two
become one. `kind-stationflow/src/test/resources/i18n/format.json` is the
shared vectors file from the same commit, and `ShackFormatVectorsTest` runs
every vector in `testDebugUnitTest`.

To refresh:

```sh
C=$(git -C ~/ohs-libs log -1 --format=%h -- kotlin/shack-i18n spec/vectors/i18n)
F=android/kind-stationflow/src/main/java/com/openhamshack/i18n/ShackFormat.kt
# keep the 8-line header, naming the new commit; replace everything below it
{ head -8 $F | sed "2s/commit [0-9a-f]*/commit $C/"
  cat ~/ohs-libs/kotlin/shack-i18n/src/main/kotlin/com/openhamshack/i18n/ShackFormat.kt
} > $F.new && mv $F.new $F
cp ~/ohs-libs/spec/vectors/i18n/format.json android/kind-stationflow/src/test/resources/i18n/format.json
```

then run the unit tests. Never edit the copy here: change ohs-libs and copy
again, or the platforms drift apart. If the vectors' `version` changes, the
test's version check fails on purpose: read what changed before updating
it.

## The check

`shack-i18n-check` (ohs-libs, contract §3) fails on a user-visible literal
outside the catalogs. It runs from a pinned wheel in `tools/vendor/` through
`tools/i18n.py`, which needs only `python3` 3.11 or newer:

```sh
python3 tools/i18n.py check        # from the repo root
```

**It runs before every unit test run**: `./gradlew testDebugUnitTest`
depends on the `i18nCheck` task, so a finding fails the build. Android Lint
also has `HardcodedText` and `SetTextI18n` as errors (`android/lint.xml`)
for XML layouts, of which there are none yet.

What it reads (`.i18n-check.toml`): every Kotlin source and `res/` XML
except unit tests, Gradle output, `tools/fakeflow.py` (a test double) and
the banner generator, each excluded with its reason. Besides the built-in
sinks (`Text(`, `contentDescription =`, …) it treats `TvSection(`,
`TvTextDialog(` and the session's `say(` as user-visible. A new composable
that takes display text belongs in that list.

A finding looks like:

```
android/kind-stationflow/…/TunePanel.kt:70:14: user-visible literal "Tune" passed to Text(); use stringResource()
```

Fix it by moving the text to the catalog. Never silence it.

### The baseline: `i18n-pending.txt`

Every literal that was in the code when the check arrived (M1): 46 of
them, one line per file and literal. They are the M3 work list. When you
convert one, its line stops matching and the check fails with "matched
nothing"; run

```sh
python3 tools/i18n.py baseline
```

to drop it, and commit the shorter file with the conversion. `baseline`
never adds a line. `--add-new` exists only for writing the first baseline
and is not a way to make a new literal pass. **A converted string never goes
back into this file.**

### The allow-list: `i18n-allow.txt`

For literals a person reads that are not language, so no translation
should touch them. One line each: `glob | "JSON literal" | reason`. The
reason is required, and an entry that matches nothing fails the check, so
the list cannot rot. Today it holds the Icom's own panel labels: `VFO A`,
`VFO B` and the LCD's `SPLIT`. Mode names such as `FT8` and `QO-100` are
already in the shared terms list the checker carries. Band names and units
are not exceptions: they go through ShackFormat or a catalog pattern
(`%1$s km`).

## Not done yet

- The rest of the kind (TV screen, Tune panel, SSTV, the session's
  messages) and `core-candidates`: the 46 baseline lines, M3.
- The pseudo-locale UI test (contract §5 item 2) that proves a second
  catalog loads and nothing clips.
- Typed frequencies (`parseTypedFrequency` in the Tune panel) still use
  their own parser rather than `ShackFormat.parseFrequency`, which would
  need the field's unit decided: the panel accepts MHz, kHz and Hz without
  a unit by magnitude.
- The check does not read `AndroidManifest.xml`, so a string used only
  there (such as `app_name`, before the picker showed it) is reported as an
  unused key. That is a warning, not a failure.
